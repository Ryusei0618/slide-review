# 逐页审阅页（PPT，可交互版）

交付物渲染图铺成本地网页：用户**单击元素直接改**（文字/字号/加粗/颜色/位置大小，可
拖拽移动缩放）、**替换图片**（上传本地图，自动压缩，保位置尺寸）、**删除形状**（含其动画
引用），攒改动清单**应用直接写回源文件**并自动重渲染；**实时预览**（写临时副本渲染，不碰
原件，角标一键还原）；**应用后可一键撤销**，且每次应用自动留存改动页的前后渲染图，弹窗/
托盘可看**前后对比**（撤销即失效）。标注四种（顶栏切换）：▭ 框选 / ↗ 箭头（汇总带「起点→
终点」方向语义）/ ✎ 画笔 / ◯ 椭圆，意见按 **P页-序 全局编号**，顶部「意见列表」侧栏集中
查看、双向跳转高亮，每条可勾选**已处理**（划线沉底、不进汇总）。有动画的页带**逐帧播放器**
（`--frames` 出帧图，对帧提意见自动带帧号——动画意见从口头描述变成指帧描述）。

## 环境要求

- **Windows + PowerPoint 或兼容 WPS**（COM 组件 `PowerPoint.Application`）+ **PowerShell 7**
  （pwsh，渲染走 COM 导出 PNG）；macOS/Linux 无法渲染。
- **Python 3.9+**，包：`python-pptx`、`lxml`、`Pillow`。
- 本 skill 的工具脚本在 `scripts/`（加载本 skill 时给出的 base directory 即 skill 根，
  脚本按 `<base>/scripts/<名字>.py` 调用）。docx 文档审阅需要额外工具包（apply_changes_docx.py
  三件套），其目录设入环境变量 `SLIDE_REVIEW_DOCX_TOOLKIT` 即启用，缺省仅支持 PPT。

## 生成与服务

```bash
# 生成（COM 渲染全册 + 递归解析形状树含组内子形状；--frames 为有动画的页逐帧渲染）：
python "<base>/scripts/make_review.py" "<成品.pptx>" [--out DIR] [--no-render] [--frames] [--port 端口]
# 服务（必须用 serve_review.py：含 /apply /preview /revert 接口 + no-store 防缓存；
# 用 http.server 起的话点选/预览/撤销全部失效）：
python "<base>/scripts/serve_review.py" <端口> "<out 目录>"
```

## 服务与交付纪律

1. **每次交付换一个没用过的端口**；起服务前 `netstat -ano | grep :<端口>` 查占用——
   Windows 允许重复绑定且不报错，连到旧进程用户看到的就是上一份文档
2. 服务用后台方式起，起完后 **curl 验证响应 body** 的 `"title"` 确认是本文档；
   汇报里给完整 URL（不要粗体星号紧贴 URL，用户会点进 `/**` 路径 404）
3. 交付汇报必须包含审阅页 URL，缺了按未完成处理
4. **一切重建 index.html 的调用都必须同带 `--frames`**（帧图已在则自动复用秒回，带上
   永远无代价；漏带则帧数据被冲、播放器整块消失——apply/revert 尾部的自动重建已内置，
   手动重建别漏）
5. 验证页面交互时：合成鼠标事件对 sticky 顶栏按钮不生效，改页面内 `element.click()`；
   点击测试的自测坐标必须取自渲染图视觉位置，不能从数据 bbox 反推（数据错位时假阳性）
6. `confirm` 对话框会阻塞页面：自动化测试触发了 alert/confirm 时先处理对话框

## 用户反馈回来后

- **【先合并已应用改动，再落实意见——顺序不可反】**：处理圈选/文字意见前，**第一步先盘点
  `review/<out>/apply/` 目录**——存在 `pending_<ts>.json`（每次「应用」的改动清单）+
  `backup_*.pptx`（应用前备份链）即说明用户点过「应用」，交付文件里已含这些改动。
  此时**严禁直接重放构建管线覆盖交付文件**——管线产物不含用户改动，重跑即静默冲掉。
  正确做法按交付物归属二选一：① 交付物来自**可重放管线**：把 pending 清单逐条**合并进
  构建源**，与本次意见一起重跑管线；② **不可重放**：走 patch 直接在现交付文件上改。
  合并后逐条核对清单（条数、字段值）再交付，汇报里写明合并了哪几处。
- 用户点过「应用」的改动已写回源文件并自动重建了审阅页（备份 + 渲染 diff + 回滚纪律
  内置），处理后续反馈以应用后的成品为现状；撤销入口在应用完成弹窗与托盘
- 反馈里的英寸坐标与形状 id 直接对照形状清单定位（`scripts/dump_shapes.py` 可出清单），
  不必重新渲染目测
- 改动 fields 是**相对课件现状的绝对值**；「元素意见」与画框/箭头/笔迹意见按汇总处理
  （带页码 + 形状 id + 英寸坐标；箭头意见带方向）

## 写回/预览的架构事实（改代码前必读）

- 写回三件套 apply/preview/revert_changes.py：preview 把改动写**临时副本**渲染涉及页，
  绝不触碰原件，与应用共用同一套写回原语（apply_to_prs）——预览所见 = 应用所得
- 应用自带保护：写回前检测文件占用 → 备份 → python-pptx 写回 → COM 全册重渲染 →
  **非改动页与旧图逐像素 diff（应零差异，违反即从备份回滚）** → 重建审阅页
- 替换图片：前端 canvas 压到长边 1920（PNG 保透明），dataURL 走 body（上限 32MB），
  写回时新建 image part 并把 blip r:embed 改指新 part（旧 part 留存，不破坏同图共享引用）
- 删除形状：先清 timing 里该 spid 的击组（防悬空引用放映异常）再删节点
- 箭头标注几何在渲染像素空间算角度、长度用「相对图层宽度的百分比」（固定 px 会随显示
  宽度拉长穿头）；前端新加构建期调用的 helper 必须定义在脚本顶部工具区（TDZ 会炸整个
  初始化，且首载无数据时不报错、有数据才炸）
